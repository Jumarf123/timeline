# Форматы и поиск / Formats and search

## Поиск

**Авто** распознаёт `regex:`, начальные флаги `(?i)` / `(?-i)` и `ext:`. Обычные слова ищутся буквально. Для выражения без флагов, например `!!.*!2025/\d{2}/\d{2}:\d{2}:\d{2}:\d{2}!0!`, выберите **Regex**. **Текст** отключает интерпретацию синтаксиса. Переключатель регистра действует по умолчанию; явные флаги внутри выражения имеют приоритет.

```text
ext:.exe;.jar;.zip;.rar;.py;.bat regex:(?i)(meteor|liquid[-_]?bounce|cheat[\s_-]?engine)
(?i)(2023\/03\/09:17:11:30|2025\/04\/16:11:03:38)
(?i)([a-z]:\\[^:<>"]+\.\w{2,4}):([^:\s\]]+)
```

В последнем примере `\\` обозначает буквальную обратную косую черту Windows-пути, `\.` — точку перед расширением. Одинарная `\` перед `[` изменяет смысл regex. Программа не переписывает выражение за пользователя.

Фильтр `ext:` и regex должны совпасть в одной ячейке с именем или путём файла. Расширение сравнивается без учёта регистра; для `file.exe:stream` используется `exe`. Это поддержка указанной формы запросов Everything, а не всего языка Everything. Списки расширений разделяются `;`, альтернативы regex — `|`.

Используется Rust regex: Unicode, группы, альтернативы и inline-флаги поддерживаются; lookaround и обратные ссылки не поддерживаются. Неверное выражение вызывает сообщение об ошибке, сохраняя предыдущий результат. Шаблон компилируется один раз на запрос, поиск выполняется параллельно.

## Просмотр и копирование

- JSON: таблица значений или документ с деревом, форматированным и исходным текстом. Большие числа не округляются. JSONL допускает объекты, массивы и скалярные записи.
- Документ читается фрагментами до 8 MiB, с переходом вперёд/назад. В неполном фрагменте JSON дерево может быть недоступно; исходный текст остаётся доступным. Поиск таблицы охватывает весь файл, поиск внутри документа — открытый фрагмент.
- В Markdown HTML очищается; внешние изображения и ссылки не загружаются. Исходник сохраняет разметку.
- Нетабличные TXT/LOG открываются как документ: перенос строк, номера строк, Ctrl+F, выделение и копирование текста. Перенос можно отключить; выбор сохраняется.
- Выделите диапазон мышью либо удерживайте Shift при щелчке/навигации. Ctrl+C копирует TSV: значения с табуляцией, кавычками и переносами экранируются для вставки в Excel. Для одной ячейки копируется исходное значение.
- Копирование диапазона ограничено миллионом ячеек и 64 MiB. Для большего объёма используйте экспорт CSV. Ограничения показываются явно; содержимое диапазона не обрезается молча.
- Сетка сокращает длинные ячейки для быстрого отображения; поиск, диапазонное копирование и экспорт используют полные значения.
- В просмотре ячейки текстовые hex-значения также распознаются: `AA BB`, списки с `0x`, непрерывный hex, `\xHH`, SQL `X'…'` и массивы байтов. Можно переключить читаемый текст и исходное значение. Обрабатывается только полностью корректная hex-запись до 1 MiB; короткие адреса и произвольный текст не выдаются за закодированную строку.
- Служебные `$raw/…` столбцы ESE/SQLite и `Raw data` реестра скрыты по умолчанию; их можно включить в списке столбцов.

## Автоматическое определение формата

| Содержимое | Представление и особенности |
|---|---|
| CSV, TSV, PSV | Разделители, кавычки, многострочные поля, Unicode; ручные настройки формата и кодировки. |
| TXT, LOG | Распознавание разделителей и таблиц фиксированной ширины. Для TXT автоопределение можно отключить. Нетабличный текст остаётся построчным. |
| JSON, JSONL, NDJSON | Определение также по содержимому; вложенные поля в таблице используют JSON Pointer. |
| MD, JS, TS, Python, PowerShell, shell, YAML и др. | Исходник с сохранением отступов; известные языки имеют подсветку. |
| EVTX | Многопоточный разбор блоков, поля System/EventData и другие вложенные данные, идентификатор и время записи. Повреждения дают строки/предупреждения об ошибках. |
| XML | Элементы, атрибуты, текст, повторения, комментарии и инструкции обработки; отдельные пути полей. DTD сохраняется как текст, внешние сущности не загружаются. |
| Autoruns ARN | Контейнер OLE Compound File: динамические поля, записи и времена. Неизвестные поля сохраняются. Проверено на предоставленном ARN и синтетических вариантах структуры; несовместимый/повреждённый контейнер может потребовать просмотра байтов. |
| ESE / EDB | Сначала Windows ESENT в режиме чтения, затем резервный парсер с предупреждением при отказе ESENT. Чистые БД дают лучший результат; занятая/dirty БД может требовать согласованную копию и журналы транзакций. Приложение не выполняет восстановление исходной БД. |
| Registry DAT | Hive определяется по сигнатуре `regf`; ключи, значения и метаданные. Любое расширение DAT само по себе не определяет формат. |
| SQLite / DB | Таблицы, исходные имена полей, целые числа и BLOB. Для согласованного состояния активной WAL-базы нужна копия вместе с её WAL. |
| USN Journal | Записи журнала и имена файлов, причины изменений; чтение `$UsnJrnl:$J` через Windows API либо NTFS. Другие потоки, включая `$Max`, не выдаются за журнал записей. |
| Неизвестный бинарный файл | Извлечённые UTF-8/UTF-16 строки с точными смещениями, длиной и кодировкой. Исходные байты доступны в режиме Hex. Это вероятный текст, а не универсальная расшифровка неизвестного формата. |

## Занятые файлы и права

В бинарных полях EDB, registry DAT, SQLite и ARN программа показывает распознанные строки, а исходный hex сохраняет отдельно. Например, UTF-16 URL после бинарного заголовка становится читаемым URL. Неизвестный/повреждённый registry DAT или ESE переходит к извлечению строк с предупреждением об ошибке структурного разбора. Сжатие, шифрование и уже утраченные данные нельзя универсально восстановить по одному расширению файла.

Обычные файлы открываются с блокировкой записи на время просмотра. Если другой процесс пишет в файл, Timeline пытается создать временную копию с проверкой размера и времени изменения. Для Windows Event Log доступен экспорт средствами Windows; для защищённых локальных NTFS-файлов — чтение через том. Права повышаются только после выбора соответствующей кнопки и подтверждения UAC; настройки и путь передаются новому окну.

UAC не гарантирует доступ к любому файлу: ограничения файловой системы, шифрование, повреждение и сжатые потоки NTFS могут препятствовать чтению. Ошибка показывается пользователю. Исходники не восстанавливаются и не изменяются, временные файлы удаляются после закрытия данных. Снимок активно изменяемого файла не равнозначен транзакционно согласованной копии БД.

## English quick reference

Auto search recognizes `regex:`, leading inline flags and `ext:`; select Regex for patterns without such a prefix. Literal mode treats everything as text. Extension and regex conditions apply to the same cell. Rust regex supports Unicode and inline flags, but not lookaround or backreferences.

Document view loads up to 8 MiB at a time. Table search covers the entire dataset; document search covers the loaded fragment. Clipboard ranges preserve complete values and visible column order, up to one million cells / 64 MiB; use CSV export above that. Format support is based on file signatures and known structures, with explicit warnings and raw-byte fallback for unsupported data. Elevation still depends on Windows permissions and filesystem capabilities.
